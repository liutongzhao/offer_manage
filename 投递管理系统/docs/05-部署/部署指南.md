# 部署指南 —— 云服务器（Docker Compose）

> 目标：把本系统部署到云服务器，公网随时访问，带访问密码，数据可备份可恢复。
> 架构：`浏览器 → :80 Nginx(前端+密码+反代) → backend(uvicorn:5112, 内网) / minio(:9000 预签名直连)`

---

## 一、架构与端口规划

| 端口 | 服务 | 对公网 | 说明 |
|------|------|--------|------|
| 80 | Nginx（前端 + `/api` 反代 + basic auth） | ✅ 开放 | 全站访问密码 |
| 9000 | MinIO S3 API | ✅ 开放 | 附件预签名 URL 浏览器直连，签名保护 |
| 5112 | 后端 uvicorn | ❌ 仅内网 | 只经 Nginx 反代访问 |
| 9001 | MinIO 管理台 | ❌ 仅 127.0.0.1 | 需要 SSH 隧道才可访问 |

**云安全组 / 防火墙**：只需放行 `80` 和 `9000`（TCP）。5111/5112/9001 一律不放。

---

## 二、服务器准备（一次）

```bash
# 1. 装 Docker（Ubuntu/Debian 官方脚本；CentOS 类似）
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 2. 把当前用户加进 docker 组（免 sudo，重新登录生效）
sudo usermod -aG docker $USER
```

## 三、拿代码 + 生成配置

```bash
# 1. 服务器上拉代码（推荐 git；或本机打包 scp 也行）
git clone <你的仓库地址> /opt/qiuzhao
cd /opt/qiuzhao/投递管理系统/deploy

# 2. 生成后端环境变量
cp backend.env.example backend.env
vim backend.env
#   必改三处：
#   MINIO_EXTERNAL_ENDPOINT=<服务器公网IP>:9000
#   MINIO_ROOT_PASSWORD=换一个强密码
#   （MINIO_ROOT_USER 也可顺手改掉）

# 3. 生成网页访问密码（替换 cuz 为你的用户名，回车输两遍密码）
sudo apt-get install -y apache2-utils   # 提供 htpasswd；或用下述 openssl 方式
htpasswd -c htpasswd cuz
#   没有 apache2-utils 时用： printf "cuz:$(openssl passwd -apr1)\n" > htpasswd
```

## 四、迁移本地数据（一次）

本机（Mac）执行，把现有数据库和附件搬上去：

```bash
# SQLite 数据库
scp ~/WorkBuddy项目/秋招投递/投递管理系统/backend/app/data/app.db \
    服务器用户@服务器IP:/opt/qiuzhao/投递管理系统/deploy/app-data/app.db

# MinIO 附件数据（整个目录）
rsync -av ~/WorkBuddy项目/秋招投递/投递管理系统/minio-data/ \
    服务器用户@服务器IP:/opt/qiuzhao/投递管理系统/deploy/minio-data/
```

> 服务器上先 `mkdir -p app-data minio-data` 再传。注意 MinIO 数据属主要一致（都是 root/容器用户时无需处理）。

## 五、启动

```bash
cd /opt/qiuzhao/投递管理系统/deploy
docker compose --env-file backend.env up -d --build
```

首次构建 5~10 分钟（拉镜像 + 编译前端）。完成后验证：

```bash
docker compose ps                     # 三个容器 Up
curl -s http://127.0.0.1/api/v1/health -u cuz:你的密码   # 应返回 {"code":0,...}
```

浏览器打开 `http://服务器IP/` → 输入 htpasswd 设置的用户名密码 → 能看到看板、能打开附件图片即部署成功。

## 六、日常更新（改了代码要重新发版）

```bash
# 服务器上拉最新代码并重建（数据在挂载卷里，重建不丢）
cd /opt/qiuzhao && git pull
cd 投递管理系统/deploy
docker compose --env-file backend.env up -d --build backend web
```

## 七、数据备份与恢复

**自动备份**（服务器 crontab，每天凌晨 3 点）：

```bash
crontab -e
# 加一行：
0 3 * * * cd /opt/qiuzhao/投递管理系统/deploy && zsh backup.sh ./backups >> backup.log 2>&1
```

**手动备份**：`zsh backup.sh ./backups`

**恢复**（灾难重建时）：

```bash
# 1. 恢复 SQLite
docker cp backups/<时间戳>/app.db offer-backend:/tmp/app.db
docker exec offer-backend sh -c "cp /tmp/app.db /app/data/app.db"
docker compose restart backend

# 2. 恢复 MinIO（停服务后直接覆盖数据目录最稳）
docker compose stop minio
cp -r backups/<时间戳>/minio/* minio-data/
docker compose start minio
```

## 八、后续升级：HTTPS（有域名时）

目前用 IP + HTTP + 密码已可用。拿到域名后推荐换 Caddy 自动签证书：

1. 安全组放行 443
2. `docker-compose.yml` 里 web 端口改 `127.0.0.1:8080:80`（不再直接暴露）
3. 加一个 caddy 服务：`caddy:2`，端口 `80:80 / 443:443`，Caddyfile 写 `你的域名 { reverse_proxy web:80 }`，证书全自动
4. 注意：换成 HTTPS 后 `MINIO_EXTERNAL_ENDPOINT` 也要跟着走域名（如 `minio.你的域名:9000` + 给 9000 套 Caddy 反代），预签名才能继续用

## 常见问题

- **附件图片刷不出来**：90% 是安全组没放行 9000，或 `backend.env` 里 `MINIO_EXTERNAL_ENDPOINT` 填错（必须是浏览器可达的 `公网IP:9000`）
- **基础认证弹窗每次都出**：正常，浏览器会记住；换了浏览器/无痕模式会再问
- **`docker compose up` 报 htpasswd 不存在**：先按第三节第 3 步生成
- **上传大文件 413**：nginx.conf 里 `client_max_body_size 50m`，按需调大
- **服务器在国内拉不动镜像**：Dockerfile 已配 npmmirror / 清华 PyPI 源；基础镜像可配镜像加速器
