# 部署指南 —— 实际部署版（2026-09-04 上线）

> 生产环境：`https://offer.cuzisme.com`（全站 basic auth）
> 服务器：117.72.219.41（SSH 别名 `jingdong`），Ubuntu 22.04，nginx 系统级管理，证书走 certbot
> 本文记录**实际部署形态**与日常操作，与早期 compose 方案不同（MinIO 已独立为基础服务）。

---

## 一、当前形态

```
浏览器 ──HTTPS──> offer.cuzisme.com (宿主机 nginx, 443)
                    ├─ /            → /opt/offer/dist        前端静态
                    ├─ /api/        → 127.0.0.1:5112         offer-backend 容器
                    └─ /qiuzhao     → 127.0.0.1:9000         MinIO（预签名代理，无密码）
```

| 组件 | 位置 | 说明 |
|------|------|------|
| MinIO 基础服务 | 容器 `minio` | 数据 `/opt/minio/data`，凭据 `/opt/minio/minio.env`；S3 API 127.0.0.1:9000、管理台 127.0.0.1:9002（SSH 隧道访问）；挂在共享网络 `base-net`，供服务器上多个应用共用 |
| 后端 | 容器 `offer-backend` | 镜像 `offer-backend:local`，仅内网 5112；数据卷 `/opt/offer/app-data`（SQLite）；`/opt/offer/backend.env` 存配置 |
| 前端 | `/opt/offer/dist` | 宿主机 nginx 直接托管 |
| nginx vhost | `/etc/nginx/sites-available/offer_cuzisme_com` | 证书 `/etc/letsencrypt/live/offer.cuzisme.com/`，certbot 自动续期 |
| 访问密码 | `/etc/nginx/offer.htpasswd` | 明文密码备份在服务器 `/root/.offer-basic-auth-pass` |
| 源码 | 服务器 `/opt/offer/src`（rsync 自本机） | 仓库 github.com:liutongzhao/offer_manage.git |

安全组/防火墙只放行 22/80/443，9000/9001/9002/5112 均不对公网。

## 二、日常发版（改了代码）

本机执行：

```bash
cd ~/WorkBuddy项目/秋招投递/投递管理系统
# 前端重新构建
cd frontend && NODE_OPTIONS='' npm run build && cd ..
# 同步代码与产物
rsync -a --delete --exclude '.venv' --exclude '__pycache__' --exclude 'app/data' --exclude '.env' --exclude '.pytest_cache' backend/ jingdong:/opt/offer/src/backend/
rsync -a --delete deploy/ jingdong:/opt/offer/src/deploy/ --exclude 'backend.env' --exclude 'htpasswd' --exclude 'minio-data' --exclude 'app-data' --exclude 'backups'
rsync -a --delete frontend/dist/ jingdong:/opt/offer/dist/
```

服务器执行（SSH 到 jingdong）：

```bash
docker build -q -t offer-backend:local -f /opt/offer/src/deploy/Dockerfile.backend /opt/offer/src
docker rm -f offer-backend
docker run -d --name offer-backend --restart unless-stopped \
  --network base-net -p 127.0.0.1:5112:5112 \
  --env-file /opt/offer/backend.env \
  -v /opt/offer/app-data:/app/data \
  offer-backend:local
```

只改前端时跳过后端两步；只改后端时跳过构建/同步 dist。

## 三、数据备份与恢复

备份脚本 `deploy/backup.sh`（SQLite 一致性备份 + mc 镜像桶），服务器上挂 crontab：

```bash
0 3 * * * cd /opt/offer/src/deploy && cp /opt/offer/backend.env . && zsh backup.sh /opt/offer/backups
```

恢复：

```bash
# SQLite
docker cp /opt/offer/backups/<时间戳>/app.db offer-backend:/tmp/app.db
docker exec offer-backend cp /tmp/app.db /app/data/app.db
docker restart offer-backend
# MinIO
docker stop minio && cp -r /opt/offer/backups/<时间戳>/minio/* /opt/minio/data/ && docker start minio
```

## 四、常用运维

```bash
# 看后端日志
docker logs -f offer-backend --tail 100
# 改网页访问密码
htpasswd /etc/nginx/offer.htpasswd cuz && systemctl reload nginx
# MinIO 管理台（本机浏览器配合 SSH 隧道）
ssh -L 9002:127.0.0.1:9002 jingdong   # 然后开 http://127.0.0.1:9002
# 新应用接入 MinIO
docker network connect base-net <应用容器>   # 然后 endpoint 用 minio:9000
```

## 五、已知坑位

- 服务器 `docker pull` 偶发 `unexpected EOF`，重试即可
- 服务器 shell 里 curl 需 `--noproxy '*'`（有代理环境）
- MinIO 管理台用 9002（9001 已被 next-server 占用）
- `MINIO_EXTERNAL_ENDPOINT=https://offer.cuzisme.com`：预签名 URL 走域名；nginx 的 `location /qiuzhao` 不能带尾斜杠（SDK 会请求 `/qiuzhao?location=`）
