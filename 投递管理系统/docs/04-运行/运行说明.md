# 秋招投递管理平台 · 运行说明

前后端分离架构：**前端 Vue3 + TypeScript + Vite**，**后端 FastAPI + SQLAlchemy + SQLite**，**文件存储 MinIO**。

## 端口约定

| 服务 | 端口 |
| --- | --- |
| 前端 Vite dev server | **5111** |
| 后端 FastAPI（uvicorn） | **5112** |
| MinIO API / 控制台 | 9000 / 9001 |

## 目录结构

```
投递管理系统/
├── backend/          # FastAPI 后端
│   ├── app/          # 应用代码（api / services / repositories / models / storage / core）
│   ├── requirements.txt
│   ├── .env          # 本地配置（不入库）
│   └── app/data/     # SQLite 数据库文件（不入库，首次启动自动建库）
└── frontend/         # Vue3 前端
    ├── src/
    │   ├── api/        # 接口封装（与后端 /api/v1 对齐）
    │   ├── constants/  # 枚举单点定义（状态/类型/渠道，与后端 constants.py 同步）
    │   ├── styles/     # 设计令牌 tokens.css
    │   ├── components/ # 业务组件（状态标签/时间线/看板/附件墙/表单抽屉等）
    │   ├── views/      # 9 个页面
    │   ├── stores/     # Pinia 状态
    │   ├── router/     # 路由
    │   └── types/      # TS 类型（与后端 schema 对齐）
    └── package.json
```

## 后端启动

```bash
cd 投递管理系统/backend
source .venv/bin/activate              # 首次需创建：python -m venv .venv && pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 5112
# 接口文档：http://127.0.0.1:5112/docs
# 健康检查：http://127.0.0.1:5112/api/v1/health
```

依赖：fastapi、uvicorn、sqlalchemy、pydantic、pydantic-settings、minio、python-multipart、python-dotenv。

## 前端启动

```bash
cd 投递管理系统/frontend
npm install                          # 安装依赖
npm run dev                          # 开发服务器 http://127.0.0.1:5111
# 生产构建：npm run build （产物在 dist/）
```

前端通过 Vite 代理把 `/api` 转发到后端 `127.0.0.1:5112`，无需额外跨域配置（CORS 已同步配置 5111）。

## MinIO（本地对象存储）

开发环境用 Docker 启动：

```bash
docker run -d --name offer-minio -p 9000:9000 -p 9001:9001 \
  -e "MINIO_ROOT_USER=offer_admin" \
  -e "MINIO_ROOT_PASSWORD=offer_password_123" \
  -v "$(pwd)/minio-data:/data" \
  minio/minio server /data --console-address ":9001"
```

控制台 http://127.0.0.1:9001 ，桶 `qiuzhao` 自动创建。凭据在 `backend/.env` 中配置（见 `.env.example`）。

附件与备份对象均存于该桶：附件在 `附件/{投递ID}/` 前缀，库文件备份在 `备份/` 前缀。

## 数据安全

- **备份**：设置页「立即备份」把 SQLite 库文件复制到 MinIO。
- **恢复**：设置页选择备份点恢复（高危操作，需输入「确认恢复」），恢复后需重启后端。
- **软删除**：删除的投递进入回收站（设置页可恢复/彻底删除）；归档的投递不进默认列表。

## 本机环境注意（CodeBuddy 沙箱）

本环境的 Node 被注入了 broker 文件系统钩子，会拦截 `npm install` 的目录创建导致失败。
若遇到 `CODEBUDDY_BROKER_DENY / Brokered host mkdir` 报错，安装前临时清空注入即可：

```bash
NODE_OPTIONS="" npm install --registry=https://registry.npmmirror.com
```

在普通本机（无此 broker）上直接 `npm install` 即可。
