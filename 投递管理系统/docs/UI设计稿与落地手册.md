## 0. 阅读约定

### 0.1 编号体系

沿用 `界面设计方案.md` 的编号，新增 `UI-FG-*`（Figma 规范）：

| 代码 | 类别 | 代码 | 类别 |
| --- | --- | --- | --- |
| `PG` | 页面 / 浮层 | `FG` | Figma 规范（画板、图层、组件、变量） |
| `CP` | 组件 | `IX` | 交互流程 |
| `LY` | 布局 | `EDGE` | 边界场景 |

### 0.2 状态标记

| 标记 | 含义 |
| --- | --- |
| `[沿用]` | 现有代码已有，本文件仅规范设计 |
| `[新建]` | 需新建页面/浮层 |
| `[待定]` | 依赖未确认项 |

### 0.3 命名语言（遵循 ADR-003）

| 对象 | 语言 | 示例 |
| --- | --- | --- |
| 画板名、图层名、设计说明 | **中文** | `PG-001 · 投递看板 · 桌面1440 · 默认` |
| 组件集名、变体属性名与值 | **英文** | `Base/Button`、`Variant=Primary` |
| 页面文案 | **中文** | 「新增投递」「针对性修改说明」 |

> **为什么组件名用英文**：Figma 组件名会与前端组件文件名一一对应（`Base/Button` ↔ `AppButton.vue`）。英文可保证设计稿与代码对得上，且 Figma 的变体属性排序、搜索、Dev Mode 代码提示在英文下更可靠。画板与图层是给人看的，用中文。

### 1.2 页面状态画板清单

每个路由级页面需出以下状态画板（这是最容易被漏掉的）：

| 状态 | 是否必出 | 说明 |
| --- | --- | --- |
| 默认（有数据） | ✅ 必出 | 主画板 |
| 加载中 | ✅ 必出 | 骨架屏（列表/卡片）；统计卡用占位块 |
| 空数据（首次） | ✅ 必出 | 带引导行动的空状态 |
| 无结果（筛选/搜索后） | ✅ 必出 | 与「空数据」文案不同，带「清空筛选」 |
| 网络异常 | ✅ 必出 | 后端未连接/请求失败，带「重试」 |
| 加载更多（时间线） | 选做 | 仅 PG-003 |
| 编辑态 | 选做 | 仅行内编辑、看板拖拽涉及 |
| 权限受限 | ❌ 不出 | 单人本地系统无权限模型，见 EDGE-05 |

> **画板数量估算**：9 页面 × 5 必出状态 + 浮层 9 × 2（默认/加载）+ 全局 6 ≈ **69 个画板**。实际可合并（如弹窗类只出默认态），建议首轮出 **45 个核心画板**，余下在实现阶段补。

### 2.5 组件状态矩阵（全组件通用）

**这是本章最重要的一张表。** 任何组件在建变体时，按下表逐格检查是否覆盖。

| 状态 | 视觉表现 | 交互行为 | 何时出现 |
| --- | --- | --- | --- |
| **默认 Default** | 基础样式（见设计方案 §4） | 可点击 | 常态 |
| **悬浮 Hover** | 背景/描边加深一档；卡片加 `--shadow-md` + `translateY(-1px)`；`cursor: pointer`；过渡 120ms ease-out | 可点击 | 鼠标悬停 |
| **点击/按下 Pressed** | 主色 → `--color-primary-700`；**无位移、无缩放**（避免整页抖动） | 可点击 | 按下未松开 |
| **聚焦 Focus** | `:focus-visible` 显示 2px 主色描边 + 2px offset；输入框额外 3px 主色 10% 光晕 | 可键盘操作 | 键盘 Tab 或点击输入框 |
| **激活 Active/Selected** | 主色填充或主色描边；导航项白字；视图切换选中态 | 表示「当前是这个」 | 导航、Tab、筛选器选中 |
| **禁用 Disabled** | 底 `#F2F4F7`、字 `#98A2B3`、描边 `#E4E7EC`、`cursor: not-allowed`；**需配 Tooltip 说明禁用原因** | 不可点击 | 条件不满足 |
| **只读 Readonly** | 底 `#F9FAFB`、字 `#475467`、描边不变、**可选中复制** | 可复制不可编辑 | 详情页字段展示 |
| **加载 Loading** | 按钮：spinner 14px + 文字改「处理中…」，**宽度锁定防抖动**；列表：骨架屏；表格：顶部 2px 进度条 | 不可点击 | 请求中 |
| **成功 Success** | Toast 绿色勾 3s；表单字段绿色描边 800ms；表格行背景 `--color-success-bg` 渐隐 800ms | — | 操作成功 |
| **空数据 Empty** | 96×96 线性插图（主色 20%）+ 主文案 + 副文案 + 行动按钮 | 按钮可点 | 无数据 |
| **错误 Error** | 控件描边 `#F04438` + 下方 12px `#B42318` 文案；Toast 红色 5s | — | 校验失败/请求失败 |

> **「禁用」与「只读」必须视觉可区分**：禁用是灰的，只读保持深色文字。两者混用会让人以为数据丢了。

### 2.6 七类边界场景的统一处理（EDGE）

| 编号 | 场景 | 统一处理方式 |
| --- | --- | --- |
| EDGE-01 | **长文本溢出** | 单行：超出 `text-overflow: ellipsis` + hover Tooltip 显示全文。多行：2 行截断 + 「展开」文字按钮。表单标签不截断（换行）。表格单元格一律单行截断 |
| EDGE-02 | **空数据（首次）** | 插图 + 「还没有 X」+ 副文案说明价值 + 主色行动按钮 |
| EDGE-03 | **无结果（筛选/搜索后）** | 插图 + 「没有符合条件的记录」+ 「试试减少筛选条件」+ 「清空筛选」次要按钮。**不显示「新增」按钮**（会造成「是不是没数据」的误判） |
| EDGE-04 | **网络/服务异常** | 顶栏下方通栏红色提示条：「无法连接到后端服务」+ 「重试」按钮。列表区显示错误态空状态 + 「重试」。**Toast 文案必须含原因**，如「保存失败：后端服务未启动」而非「操作失败」 |
| EDGE-05 | **权限受限** | **不适用**——单人本地系统，无权限模型（需求假设 A-1）。**不做 403 页面**。若未来引入多用户，需补：无权限页 + 按钮禁用态 + 操作拦截提示 |
| EDGE-06 | **超长文件名/公司名** | 文件名：中间截断保留扩展名（`柳铜罩-字…v2.pdf`）。公司名：表格内单行截断，详情页可换行 |
| EDGE-07 | **大数据量（>500 条）** | 分页（每页 20）+ 虚拟滚动（表格）。看板每列最多渲染 50 张卡，超出显示「还有 N 条，点击加载」。时间线一次 20 条 + 「加载更早」 |

- **列表视图为默认**，看板为可选。列表的信息密度远高于看板，检索场景下列表更高效；看板只在「推进流程」时好用。
- **状态标签可就地改**：改状态是最高频操作（需求 SC-4/SC-7），为此进详情页再改太重。
- **移动端禁用拖拽**：触屏拖拽卡片误操作率高，改用卡片内下拉，功能不缺失但更可靠。
- **筛选无结果时不给「新增」按钮**：那会让人以为「是不是系统里没数据」，实际只是被筛掉了。

#### 设计决策

- **详情页用独立路由，不用抽屉**：内容量（时间线 + 4 类素材 + 关联）太大，抽屉宽度撑不住；独立页面也便于分享与后退。
- **时间线占主区最大面积**：需求 S-1/S-3 的核心，给它最大空间。
- **字段变更默认折叠**：你选了全字段留痕，不折叠的话改一次表单能刷出十几条事件，时间线会被噪音淹没。
- **状态卡置右栏顶部而非左栏**：状态是「当前快照」，属于辅助信息；时间线才是主体。

- **从备份恢复**：PG-016 确认弹窗 + **需输入「确认恢复」四字**（最高危操作）→ 恢复中全屏遮罩 + 进度 → 完成后提示重启

| 断点 | 变化 |

| 场景 | 处理 |
| --- | --- |
| 从未备份 | 「上次备份：从未」+ 琥珀色提示条「建议现在备份一次，避免数据丢失」 |
| 备份失败（磁盘不足） | Toast「备份失败：磁盘空间不足（需要 128MB，剩余 40MB）」 |
| 恢复的文件不匹配 | 明确报错「备份文件版本不兼容」+ 说明期望版本 |
| 导出无数据 | 按钮禁用 + Tooltip「暂无数据可导出」 |
| 标签被引用时删除 | 二次确认显示引用数，确认后解绑 |
| 存储服务未连接 | 备份区块顶部警告条「存储服务未连接，备份将不包含附件」+ 仍允许备份数据库 |

#### 设计决策

- **恢复需输入确认文字**：这是唯一会整体覆盖数据的操作，必须最高强度拦截。
- **备份与恢复按钮视觉不对等**：备份是日常操作（主色），恢复是危险操作（次要样式 + 输入确认）。

> **同一页面的多画板用 Section 包裹**（Figma Section 功能），Section 名为 `PG-002 投递记录`，便于整体移动与查找。

### 5.3 图层命名规范

| 层级 | 命名规则 | 示例 |
| --- | --- | --- |
| 顶层区块 | 中文语义名 | `侧边导航`、`顶栏`、`内容区`、`页头`、`工具条`、`筛选条`、`主体卡片`、`分页` |
| 二级区块 | 中文语义名 | `统计卡行`、`图表区`、`待办区`、`左主区`、`右副区` |
| 组件实例 | 保留组件集名（英文），Figma 会显示变体值 | `Base/Button`（显示为 `Primary/M`） |
| 图标 | `icon/{语义名}` | `icon/promotion`、`icon/office-building` |
| 文本 | 语义名，**不用内容命名** | `页面标题`、`公司名`、`状态标签`、`表格-投递日期` |
| 分割线 | `divider/{方向}` | `divider/水平` |
| 占位/背景 | `bg/{用途}` | `bg/页面`、`bg/卡片` |

**禁止**：`Frame 123`、`Group 45`、`矩形 1`、`文本 8` 等默认名。Figma 的「Tidy up / 整理图层」可批量修复，但应在绘制时就命名。

### 5.4 自动布局（Auto Layout）建议

**通用原则**

| 场景 | 建议 |
| --- | --- |
| 几乎所有容器 | 都开 Auto Layout，避免手调坐标 |
| 尺寸模式 | 内容驱动用 **Hug contents**；需要响应式拉伸用 **Fill container**；固定值仅用于画板宽高与已知尺寸组件 |
| 间距 | 一律用 Space Variables（`space/4` 等），不手写数值 |
| 最大宽度 | 内容区 Frame 设 `Max width: 1440`，左右 `Fill` 居中 |
| 文本溢出 | 文本图层设 `Width: Fill` + `Truncate: 1 line`（表格单元格） |
| 响应式 | 需要换行的容器开 **Wrap**；需要自适应的用 `Fill` + `Min/Max width` |

**典型结构**

```
Frame「页面」(1440 × Hug)
  Auto Layout: Vertical | Gap: 24 | Padding: 24 | Max W: 1440
├─ Frame「顶栏」— Horizontal | Gap: 12 | Padding: 0 24 | H: 56 | Fill | center
├─ Frame「内容区」— Horizontal | Gap: 0 | Fill
│   ├─ Instance「Layout/SideNav」— W: Fixed 212
│   └─ Frame「主区」— Vertical | Gap: 24 | Padding: 24 | Fill
│       ├─ Frame「页头」— Horizontal | Gap: 12 | H: 56 | Fill | center
│       ├─ Frame「工具条」— Horizontal | Gap: 8 | H: 48 | Fill | center | Wrap
│       ├─ Frame「筛选条」— Horizontal | Gap: 8 | H: 40 | Fill | center
│       ├─ Instance「Business/DataTable」— Fill | Hug
│       └─ Frame「分页」— Horizontal | H: 56 | Fill | center | justify: end
```

```
Frame「卡片」(Card)
  Auto Layout: Vertical | Gap: 12 | Padding: 16 | Radius: 12 | Fill: neutral/0 | Effect: Shadow/XS
├─ Frame「卡头」— Horizontal | Gap: 8 | Hug | center
│   ├─ Text「卡片标题」— Text/H3 | Fill
│   └─ Instance「Base/Button」— Hug | margin-left: auto
└─ Frame「卡体」— Vertical | Gap: 8 | Fill
```

```
Frame「表格行」
  Auto Layout: Horizontal | Gap: 12 | Padding: 0 16 | H: Fixed 52 | Fill | center
├─ Instance「Base/Checkbox」— Fixed 16
├─ Text「公司名」— W: Fixed 140 | Truncate 1
├─ Text「岗位」— Fill | Min W: 180 | Truncate 1
├─ Instance「Business/StatusTag」— Fixed 100
├─ …
└─ Frame「操作」— Fixed 120 | justify: end
```

### 5.5 Figma ↔ 代码令牌映射

| Figma | 代码 | 说明 |
| --- | --- | --- |
| `color/brand/500` | `--color-primary-500` | 变量名去 `color/` 前缀后一一对应 |
| `space/4` | `--sp-4` | Number 变量 |
| `radius/md` | `--radius-md` | Number 变量 |
| `fontsize/body` | `--fs-body` | Number 变量（配合 Text Style 使用） |
| `Effect/Shadow/SM` | `--shadow-sm` | Effect Style |
| `Text/H1` | `--fs-h1` | Text Style（含字号/行高/字重） |
| `Business/StatusTag` | `StatusTag.vue` | 组件名一一对应 |
| 变体 `Status=Interviewing` | 枚举 `interviewing` | 值与后端枚举一致 |

**同步建议**：前端 `constants/enums.ts` 是枚举单点来源；Figma 变量导出为 JSON 后，可由脚本生成 `tokens.css`。首期手工同步即可，量不大。

## 6. 边界场景汇总表

| 场景 | 出现页面 | 处理方式 |
| --- | --- | --- |
| 长文本-单行 | 全部列表/表格 | 截断 + Tooltip 全文 |
| 长文本-多行 | 详情备注、问题答案 | 2~3 行截断 + 「展开全文」 |
| 超长文件名 | PG-006、附件区 | 中间截断保留扩展名 |
| 空数据（首次） | 全部列表页 | 插图 + 价值说明 + 主色行动按钮 |
| 无结果（筛选后） | 全部列表页 | 插图 + 「减少条件」+ 「清空筛选」，**不给新增按钮** |
| 网络/服务异常 | 全部 | 顶部通栏错误条 + 区域错误态 + 「重试」+ 含原因的 Toast |
| 存储服务未连接 | PG-003、PG-006、PG-009 | 附件缩略图破图占位 + 预览禁用 + Tooltip 说明；备份时警告「不含附件」 |
| 权限受限 | — | **不适用**（单人本地系统，无权限模型）。若未来多用户需补 403 页 |
| 数据量大 | 列表、看板、时间线 | 分页 + 虚拟滚动；看板每列上限 50；时间线每批 20 |
| 重名冲突 | PG-005、PG-012 | 保存时校验拦截 + 「查看已有」链接 |
| 关联数据存在时删除 | PG-005、PG-006 | 确认弹窗列出引用数量 + 说明后果 |
| 数字过大 | PG-001 | 千分位；>6 位用「1.2 万」+ Tooltip |
| 样本不足 | PG-008 | 图表独立判空 + 说明需要多少条 |
| 日期临期/过期 | PG-002、PG-004 | ≤3 天琥珀色加粗；已过期红色 + 警告图标 |
| 同一字段一次改多个 | PG-003 | 时间线折叠为「修改了 N 个字段」，展开看明细 |

## 7. 落地路径

### 7.1 现状说明

**当前环境没有连接 Figma 或任何设计工具**，我无法直接在画布上建组件、铺画板。所以交付分两条腿走：

| 路径 | 我能做什么 | 你需要做什么 |
| --- | --- | --- |
| **A. 照手册在 Figma 里搭** | 本文件已给到画板清单、组件变体定义、自动布局参数、图层命名——**照着做即可 1:1 还原** | 在 Figma 里建文件、铺画板、搭组件 |
| **B. 我直接生成 HTML 高保真原型** | 我可以生成可直接打开、可点击的 HTML 原型，用真实设计令牌渲染 | 打开看效果，反馈调整 |

### 7.2 设计工具选型对比

| 工具 | 类型 | 网络依赖 | 中文支持 | Variables | Auto Layout | 组件变体 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **Figma** | SaaS | 需联网（国内可能不稳） | 支持 | ✅ | ✅ | ✅ | 生态最好、Dev Mode 最成熟。**首选** |
| **即时设计 JsDesign** | SaaS 国内 | 国内直连 | 原生中文 | ✅ | ✅ | ✅ | Figma 文件可直接导入，国内替代首选 |
| **MasterGo 莫高设计** | SaaS 国内 | 国内直连 | 原生中文 | ✅ | ✅ | ✅ | **有 MCP 连接器可安装**（见 §7.3），装上后我可直接操作画布 |
| **Penpot** | 开源自部署 | 可完全本地 | 支持 | ✅ | ✅ | ✅ | 契合本项目「本地运行、隐私优先」定位，可 docker 起 |
| **Sketch** | macOS 原生 | 离线 | 支持 | 部分 | ✅ | ✅ | 仅 Mac，协作能力弱 |

**我的建议**：
- 若你 Figma 用得顺手 → **Figma**，本手册所有术语按 Figma 编写。
- 若 Figma 网络不稳 → **即时设计**，可直接导入 Figma 文件，功能基本对等。
- 若想让我直接帮你画 → **装 MasterGo 连接器**，我可以在画布上直接操作。
- 若坚持「数据不出本机」 → **Penpot**，用 docker 起，与 MinIO 一样跑在本地。

### 7.3 可安装的连接器

搜索结果显示 **MasterGo 莫高设计** 提供 MCP 连接器，支持「连接画布，让 AI 进行设计、修改、同步和获取 D2C 代码」。装上之后我可以直接在画布上建立组件与画板，不需要你手工照抄。

### 7.4 不建议的路径

**不要先画静态图再开发。** 本项目是本地单人工具、迭代快、页面结构清晰，直接在代码里用 Element Plus 实现 + 我生成的 HTML 原型验证，比维护一套 Figma 文件更快。Figma 的价值在于：**多人协作**或**需要反复评审视觉**——本项目两条都不成立。

**折中方案**：Figma 只建「00 设计系统 + 01 组件库」两个 Page（约 30 个组件），页面设计稿跳过，直接看 HTML 原型。这样组件规范有据可依，页面迭代不拖泥带水。
