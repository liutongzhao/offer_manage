# 个人求职投递管理系统 · 界面设计方案

> **文档定位**：本文件是「个人求职投递管理系统」前端的**视觉与交互基线**，定义设计令牌、页面结构、组件规格、交互与可用性要求，供开发直接还原、供设计 QA 验收比对。
> **配套文档**：
> - `需求规格说明书.md`（需求编号 REQ-*，本文件 §2/§4 引用其编号）
> - `架构设计.md`（技术分层、目录结构、命名约定 ADR-003）
> - `../投递管理要求.md`（管理总纲）
>
> **设计依托**：前端已采用 **Vue 3 + TypeScript + Vite + Element Plus + ECharts**（见 `frontend/package.json`）。本方案**不重复造组件轮子**，而是：
> 1. 用 §2 的设计令牌（CSS 变量）统一视觉语言；
> 2. 通过覆写 Element Plus 主题变量，让既有组件自然继承令牌；
> 3. 仅对 Element Plus 未覆盖的业务组件（状态标签、时间线事件、附件墙等）补充自定义组件。

## 1. 信息架构与页面清单

### 1.1 架构设计原则

| 编号 | 原则 | 说明 |
| --- | --- | --- |
| UI-IA-001 | **以「投递记录」为唯一核心** | 所有实体（公司、简历、附件、沟通、问题、待办）都围绕投递记录组织，导航不设与之平级的 competing 入口 |
| UI-IA-002 | **列表为主，详情为纵深** | 主路径是「找到那条记录」，详情页承载全部纵深信息；不做多层嵌套 |
| UI-IA-003 | **高频前置** | 每日必看（看板、待办）与每日必做（新增投递、改状态）放一级导航，配置类（设置、枚举）沉到底部 |
| UI-IA-004 | **素材入口就近** | 链接粘贴、附件上传是高频主路径（需求 §2.1），入口必须在使用它的页面内，不允许跳到独立页面操作 |
| UI-IA-005 | **导航深度 ≤ 3 层** | 一级导航 → 列表 → 详情；详情内的关联对象用抽屉，不再进新页面 |

## 2. 设计令牌（Design Tokens）

> **落地方式**：全部写入 `frontend/src/styles/tokens.css`，由 `main.ts` 全局引入；Element Plus 主题变量在 `styles/element/index.scss` 中映射到这些令牌（见 §2.9）。

### 2.1 主色 Primary

主色沿用既有品牌蓝 `#2F6FED`（`style.css` 中 `--brand` 已定义），扩展为完整色阶。蓝色传达专业、信任，契合求职场景，且与「后端开发」主投方向的类型色一致。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--color-primary-50` | `#EFF4FF` | 极浅底（选中行背景） |
| `--color-primary-100` | `#E8F0FE` | 浅底（信息类标签、提示条背景） |
| `--color-primary-200` | `#C7D9FE` | 边框（聚焦态辅助） |
| `--color-primary-300` | `#9DBEFD` | 禁用态文字（浅色底上） |
| `--color-primary-400` | `#6E9BF7` | 图表辅助色 |
| `--color-primary-500` | `#2F6FED` | **主色**：主按钮、链接、激活态、图表主色 |
| `--color-primary-600` | `#1D4ED8` | **悬停态**、主色上的深文字（对比度达标） |
| `--color-primary-700` | `#1A43B8` | 按下态 |
| `--color-primary-800` | `#183693` | 深色背景上的主色 |
| `--color-primary-900` | `#152C70` | 极深强调 |

| `--color-amber-50` | `#FEF3E2` | 强调类浅底 |

### 2.3 语义色 Semantic

| 语义 | 实心 `--color-{x}-solid` | 浅底 `--color-{x}-bg` | 深字 `--color-{x}-text` | 用途 |
| --- | --- | --- | --- | --- |
| 成功 success | `#12B76A` | `#E7F8F0` | `#067647` | 已 Offer、保存成功、完成态 |
| 警告 warning | `#F59E0B` | `#FEF3E2` | `#B45309` | 临期提醒、待处理 |
| 错误 error | `#F04438` | `#FEECEB` | `#B42318` | 已挂、删除、校验失败 |
| 信息 info | `#2F6FED` | `#E8F0FE` | `#1D4ED8` | 已投递、一般提示 |
| 中性 neutral | `#64748B` | `#F1F5F9` | `#475569` | 待投递、未开始、禁用 |

> **重要**：浅底 + 深字组合用于**所有含文字的标签/提示条**，确保正文对比度 ≥ 4.5:1（见 §6.3）。实心色仅用于状态点、图表、图标等非文本元素（要求 ≥ 3:1）。

### 2.4 业务状态色（投递状态，8 态）

对应需求 §4.2.2 的「当前状态」枚举。这是全系统最高频的视觉元素，**必须三处一致**（需求文档、后端枚举、前端令牌）。

| 状态 | 语义 | 实心点 `--status-{key}-dot` | 标签底 `--status-{key}-bg` | 标签字 `--status-{key}-text` | 图标建议 |
| --- | --- | --- | --- | --- | --- |
| 待投递 | 中性 | `#64748B` | `#F1F5F9` | `#475569` | Clock |
| 已投递 | 信息 | `#2F6FED` | `#E8F0FE` | `#1D4ED8` | Promotion |
| 笔试中 | 紫 | `#7C5CFF` | `#F0EBFF` | `#5B3FDB` | EditPen |
| 面试中 | 琥珀 | `#F59E0B` | `#FEF3E2` | `#B45309` | Microphone |
| 已 Offer | 成功 | `#12B76A` | `#E7F8F0` | `#067647` | CircleCheck |
| 已挂 | 错误 | `#F04438` | `#FEECEB` | `#B42318` | CircleClose |
| 已拒绝 | 灰 | `#98A2B3` | `#F2F4F7` | `#667085` | Remove |
| 爽约 | 深灰 | `#475467` | `#EEF0F3` | `#344054` | Warning |

**设计说明**：
- 标签 = **左侧 6px 状态点（实心）+ 中文文字（深色）**，置于浅色药丸底上。这样状态既不依赖单一颜色传达（点+文字双编码），又保证文字在任何屏幕下可读。
- 「已挂」与「已拒绝」必须视觉可区分：前者红（被动失败），后者灰（主动放弃/未推进），避免复盘时误读。
- 「爽约」为企业侧违约，用深灰区别于我方主动「已拒绝」。

### 2.6 字体与字号层级

**字体族**（沿用现有，补全等宽与数字对齐）：

```css
--font-sans: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC',
  'Hiragino Sans GB', 'Microsoft YaHei', sans-serif;
--font-mono: 'SF Mono', 'JetBrains Mono', Menlo, Consolas, monospace;
```

**字号层级**（14px 为正文基准，1.5 左右行高）：

| 令牌 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| `--fs-display` | 30px | 38px | 600 | 统计卡大数字（配 `font-variant-numeric: tabular-nums`） |
| `--fs-h1` | 24px | 32px | 600 | 页面标题（顶栏） |
| `--fs-h2` | 20px | 28px | 600 | 区块标题（卡片组标题） |
| `--fs-h3` | 16px | 24px | 600 | 卡片标题、抽屉标题、表格首列 |
| `--fs-body-l` | 15px | 24px | 400 | 表格主内容、表单输入值 |
| `--fs-body` | 14px | 22px | 400 | 正文、按钮、表格常规单元格 |
| `--fs-sm` | 13px | 20px | 400 | 次要说明、筛选标签、表头 |
| `--fs-xs` | 12px | 18px | 400 | 标签、时间戳、辅助信息 |

**字重**：400（正文）/ 500（按钮、表头、强调单元格）/ 600（标题、统计数字）。不使用 300 及以下（小字号下渲染发虚）。

**数字与时间**：所有日期、金额、数量使用 `--font-mono` + `tabular-nums`，保证表格列纵向对齐。

| --- | --- | --- |

## 5. 交互与反馈

### 5.1 动效规范

| 场景 | 时长 | 缓动曲线 | 说明 |
| --- | --- | --- | --- |
| 颜色/阴影微交互（hover、active） | 120ms | `ease-out` | 按钮、标签、导航项 |
| 展开/折叠（分组、时间线明细） | 200ms | `cubic-bezier(.4,0,.2,1)` | 高度过渡用 `grid-template-rows` 或 max-height |
| 弹窗 | 200ms 入 / 160ms 出 | 入 `cubic-bezier(0,0,.2,1)` / 出 `cubic-bezier(.4,0,1,1)` | 缩放 .96→1 + 淡入 |
| 抽屉 | 240ms 入 / 200ms 出 | 同上 | 纯位移，无缩放 |
| Toast | 150ms 入 / 150ms 出 | `ease-out` | 停留 3000ms（错误 5000ms） |
| 页面切换 | 160ms | `ease-out` | 仅淡入，不做位移（避免眩晕） |
| 表格行更新成功 | 800ms | `ease-out` | 行背景短暂 `--color-success-bg` 渐隐 |
| 看板拖拽 | 实时跟随 | 无 | 放置归位 200ms |
| 骨架屏扫光 | 1.2s | `linear` 无限循环 | — |

**减少动效**：全局响应 `@media (prefers-reduced-motion: reduce)`，将所有 transition/animation 时长归零，仅保留即时状态切换。

### 5.2 主要交互流程

#### IX-01 新增投递（含链接与简历）

| 步骤 | 交互 | 反馈 |
| --- | --- | --- |
| 1 | 点击页头「+ 新增投递」 | 右侧抽屉滑入（240ms），焦点自动落到「公司」输入框 |
| 2 | 输入公司名 | 下拉联想已有公司（支持别名搜索）；若无匹配，显示「+ 新建公司「{输入}」」选项 |
| 3 | 填写类型/岗位/城市 | 实时校验，必填项为空时保存置灰 |
| 4 | 粘贴 JD 链接 | 链接区「+ 添加链接」→ 粘贴后自动填充名称，回车即存，链接项淡入 |
| 5 | 拖拽 JD 截图到上传区 | 拖拽区高亮 → 上传中进度条 → 缩略图淡入 + Toast「已上传 1 个文件」 |
| 6 | 选择/上传简历 | 下拉选择已有版本，或上传新版本（自动默认版本号 v{n+1}） |
| 7 | 点击「保存」 | 按钮转 spinner（宽锁定）→ 抽屉关闭 → 表格顶部插入新行 + 800ms 绿色高亮 → Toast「已新增投递：字节跳动 · Java 后端」 |
| 失败 | — | 抽屉保持打开（不丢数据），顶部红色错误条 + 对应字段标红；Toast「保存失败：{原因}」 |

#### IX-02 改状态（三种入口）

| 入口 | 交互 |
| --- | --- |
| 列表行内 | 点击状态标签 → 内联下拉（状态选项 + 色点）→ 选择即保存，无需确认 |
| 详情页 | 点击「改状态」下拉 → 选择 → 若目标状态为终态（已 Offer / 已挂 / 已拒绝），弹出补充信息框（结果日期、薪资/原因）→ 保存 |
| 看板拖拽 | 拖动卡片到目标列 → 放置 → 立即保存 |

**统一反馈**：更新成功后状态标签 200ms 淡变到新色 + Toast「已更新为：面试中」；**同时自动生成时间线事件**（REQ-TRC-001）。若状态为终态，Toast 追加提示「已记录结果」。

**失败回滚**：状态标签回滚原值 + 红色描边抖动（200ms）+ Toast「更新失败：{原因}」。

#### IX-03 删除与撤销

| 步骤 | 交互 |
| --- | --- |
| 1 | 点击「删除」（危险文字按钮） |
| 2 | 确认弹窗：标题「确认删除这条投递记录？」+ 正文列出公司/岗位 + 说明「删除后可在「数据与设置 → 已归档」中恢复」 |
| 3 | 点击「确认删除」（红色实心按钮，位于右侧；左侧为「取消」次要按钮） |
| 4 | 行淡出 200ms → 列表重排 → Toast「已删除：字节跳动 · Java 后端　[撤销]」（撤销按钮 5 秒内有效） |

**设计说明**：软删除（REQ-NFR-008）必须提供撤销入口，误删成本极低时才敢用。清空全部数据需**输入确认文字**（如输入「确认清空」），不做输入确认的批量删除一律禁止。

#### IX-04 多条件筛选与搜索

| 步骤 | 交互 |
| --- | --- |
| 1 | 选择筛选条件（多选下拉）或输入搜索关键词 |
| 2 | 搜索输入**防抖 300ms** 后自动查询；下拉选择后立即查询 |
| 3 | 结果区顶部 2px 主色进度条；>300ms 显示骨架屏；表格保留旧数据直到新数据返回 |
| 4 | 结果数更新，无结果时切换空状态（带「清空筛选」） |
| 5 | 筛选条件**同步到 URL query**，刷新与分享链接可复现 |

#### IX-05 记录沟通

| 步骤 | 交互 |
| --- | --- |
| 1 | 投递详情页时间线卡右上角「+ 记一笔」→ 展开内联表单（沟通时间默认当前、对象、方式、内容摘要、我方动作） |
| 2 | 沟通时间**允许选择过去的日期**（需求 Q-3 附带说明：如「昨天 HR 加我微信」须记为昨天） |
| 3 | 勾选「生成待办」→ 显示待办时间输入，保存后同时出现在待办列表 |
| 4 | 保存 → 时间线顶部插入新事件（淡入 + 200ms 位移）→ Toast「已记录沟通」 |

#### IX-06 上传附件

| 步骤 | 交互 |
| --- | --- |
| 1 | 详情页附件卡「+ 上传」或直接拖拽文件到卡片区域 |
| 2 | 上传中：文件项显示进度条 + 百分比 |
| 3 | 成功：缩略图淡入，默认类型根据文件扩展名猜测（.png/.jpg → JD截图，.pdf → 简历），可修改 |
| 4 | 点击缩略图：图片开灯箱（支持缩放/左右切换），PDF 新标签打开（预签名 URL） |
| 5 | 删除：气泡确认 → 文件项淡出 150ms → Toast「已删除附件」 |

### 5.3 反馈方式选择原则

| 场景 | 方式 | 规格 |
| --- | --- | --- |
| 操作成功且无后续 | Toast 右上，绿色勾，3s | 最多同时堆叠 3 条，超出折叠 |
| 操作成功但需撤销 | Toast + 「撤销」文字按钮，5s | 删除类操作 |
| 操作失败 | Toast 红色，5s，文案含原因与建议 | 「保存失败：公司名称不能为空」而非「操作失败」 |
| 破坏性操作 | 确认弹窗（Dialog） | 标题疑问句，正文列影响范围，确认按钮红色 |
| 轻量确认 | 气泡确认（Popconfirm） | 表格行内删除 |
| 状态进行中 | 组件内 spinner / 进度条 | 不使用全局遮罩（本地应用，响应快） |
| 内容加载 | 骨架屏（>300ms） | 见 UI-CP-023 |
| 校验失败 | 字段内联错误 + 聚焦首个错误项 | 不同时弹 Toast（避免双重提示） |

**禁止**：成功操作使用弹窗（打断流程）；错误仅用红色描边不给文字说明；无操作入口的空状态。

## 6. 适配与易用性

### 6.1 响应式断点

| 断点 | 范围 | 侧边栏 | 内容区 | 表格 | 详情页 | 看板 |
| --- | --- | --- | --- | --- | --- | --- |
| **xs** 手机 | <768 | 隐藏，汉堡按钮唤出抽屉（覆盖式，宽 240px） | padding 16px | **转卡片流**（每卡一行：公司+岗位+状态，次要信息折叠） | 单栏，区块纵向堆叠，时间线优先 | 单列纵向，列内卡片流，不可拖拽（改用下拉改状态） |
| **sm** 平板 | 768–1023 | 折叠为图标栏 64px（Tooltip 显示名称） | padding 20px | 横向滚动，固定前 2 列（公司+岗位） | 单栏 | 横向滚动，列宽 260px |
| **md** 笔记本 | 1024–1439 | 展开 212px | padding 24px | 全列，隐藏部分次要列 | 两栏 7:5 | 横向滚动，列宽 280px |
| **lg** 桌面 | ≥1440 | 展开 212px | padding 24px，max-width 1440 居中 | 全列 | 两栏 7:5 | 横向滚动，列宽 280px |

**移动端降级原则**：本产品**桌面端优先**（本地运行、数据密集），移动端目标是「可读、可查、可应急操作」，不追求功能对等。具体降级：
- 表格转卡片流（信息密度换可读性）；
- 筛选收进底部抽屉；
- 新增/编辑抽屉全屏；
- 看板禁用拖拽，改用卡片内状态下拉（拖拽在触屏上易误操作）。

### 6.3 文字对比度（WCAG AA）

> 以下为设计取值，**实现时请用浏览器 DevTools 或 axe 复核**；任何不达标组合需调整后落地。

| 前景 | 背景 | 比值 | 判定 | 用途 |
| --- | --- | --- | --- | --- |
| `#1D2939` gray-800 | `#FFFFFF` | ≈14.8:1 | ✅ AAA | 正文 |
| `#344054` gray-700 | `#FFFFFF` | ≈11.0:1 | ✅ AAA | 次要标题 |
| `#667085` gray-500 | `#FFFFFF` | ≈5.9:1 | ✅ AA | 辅助说明 |
| `#98A2B3` gray-400 | `#FFFFFF` | ≈2.9:1 | ⚠️ | **仅用于占位符与禁用态**，不承载正文 |
| `#FFFFFF` | `#2F6FED` primary-500 | ≈4.55:1 | ✅ AA | 主按钮文字 |
| `#1D4ED8` | `#E8F0FE` | ≈7.4:1 | ✅ AAA | 信息类标签 |
| `#B45309` | `#FEF3E2` | ≈6.0:1 | ✅ AAA | 警告类标签 |
| `#B42318` | `#FEECEB` | ≈7.1:1 | ✅ AAA | 错误类标签 |
| `#067647` | `#E7F8F0` | ≈5.9:1 | ✅ AA | 成功类标签 |
| `#5B3FDB` | `#F0EBFF` | ≈7.2:1 | ✅ AAA | 紫色类标签 |
| `#475569` | `#F1F5F9` | ≈7.5:1 | ✅ AAA | 中性类标签 |
| `#CBD5E1` | `#101828` | ≈8.0:1 | ✅ AAA | 侧边栏未选中项 |

**硬性规则**
1. 正文文字对比度 ≥ **4.5:1**；≥18px 或 ≥14px 粗体的大字 ≥ **3:1**。
2. 非文本元素（状态点、图标、图表色块、输入框描边）与相邻色对比度 ≥ **3:1**。
3. `#98A2B3`（gray-400）**禁止用于正文**，仅用于占位符、禁用态、装饰图标。
4. 状态标签全部采用「浅底 + 深字」组合，不采用「深底 + 白字」（白字在中浅色底上普遍不达标）。
5. 图表配色需保证相邻色相可区分，且每个系列配文字标签，不依赖颜色单独区分。

### 6.4 可点击区域

| 元素 | 桌面最小 | 移动最小 | 说明 |
| --- | --- | --- | --- |
| 按钮 | 32×32 | **44×44** | M 号按钮 36px 高已达标 |
| 图标按钮 | 32×32 | **44×44** | 28px 视觉图标需外扩 padding 到 44 |
| 表格行 | 整行可点 | 整卡可点 | 行内按钮需 `stopPropagation` |
| 链接（文字） | 行高 ≥20px | 行高 ≥24px | 下划线标识（hover 显现） |
| 标签（筛选 chip） | 24px 高 | 32px 高 | 含 ✕ 关闭区 |
| 复选框/单选 | 16px 视觉 + 24px 热区 | 20px + 44px 热区 | 点击标签文字也能切换 |

**规则**：相邻可点击元素间距 ≥ 8px，避免误触；表格行内操作按钮组之间间距 4px，但整体视觉分组。

### 6.5 键盘与辅助

| 能力 | 要求 |
| --- | --- |
| 焦点可见 | 所有可聚焦元素 `:focus-visible` 显示 2px 主色描边 + 2px offset；**禁止** `outline: none` 无替代 |
| Tab 顺序 | 遵循视觉顺序（左→右，上→下）；弹窗/抽屉打开时焦点移入并**锁定**在容器内，关闭后归还触发元素 |
| 快捷键 | `Esc` 关闭弹窗/抽屉/灯箱；`Enter` 提交表单；`Cmd/Ctrl + K` 全局搜索；`Cmd/Ctrl + Enter` 表单保存；`/` 聚焦搜索框 |
| 跳过导航 | 首个可聚焦元素为「跳到主内容」链接（视觉隐藏，聚焦时显现） |
| 语义化 | 用 `<nav>/<main>/<header>/<table>` 语义标签；图标按钮必须带 `aria-label`；状态标签文字本身即可读，无需额外 aria |
| 屏幕阅读 | 异步更新区域（Toast、列表刷新）用 `aria-live="polite"`；错误用 `aria-live="assertive"` + `role="alert"` |
| 中文排版 | `text-wrap: pretty`；避免单行过长（正文容器 ≤ 800px）；中英文混排自动加间距不做强制干预 |

### 7.2 枚举单点定义（REQ-NFR-013）

状态、类型、渠道、附件类型等枚举**必须在 `constants/enums.ts` 单点定义**，包含 `{ value, label, colorDot, colorBg, colorText, icon }`，前端组件统一消费该文件，后端枚举同步（见需求 §7.2 Q 相关约定）。避免色值散落在各组件中导致不一致。
